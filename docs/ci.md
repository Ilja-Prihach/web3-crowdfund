# Непрерывная интеграция (CI)

Проверки контрактов выполняются автоматически в GitHub Actions. Конфигурация находится в `.github/workflows/contracts.yml`.

## Когда запускается

Workflow `Contracts CI` запускается при каждом pull request в `main` и при каждом push в `main`.

Фильтр по путям (`paths`) намеренно не используется. Проверка `Format, build, test` обязательна для слияния в `main`, а workflow, пропущенный фильтром, не сообщает статус. Из-за этого pull request без изменений в `contracts/` (например, только документация) нельзя было бы слить. Полный прогон занимает около минуты и бесплатен для публичного репозитория.

## Что проверяется

Job `Format, build, test` выполняется на `ubuntu-latest` в каталоге `contracts/`:

1. Загружает репозиторий вместе с подмодулями `forge-std` и `openzeppelin-contracts`.
2. Устанавливает Foundry.
3. `forge fmt --check` — код отформатирован по правилам Foundry.
4. `forge build --sizes` — контракты компилируются и укладываются в лимит размера байткода.
5. `forge test -vvv` — проходят все тесты, включая fuzz- и invariant-тесты.

Шаги выполняются по порядку; первый упавший шаг останавливает job.

## Защита ветки `main`

- изменения попадают в `main` только через pull request;
- для слияния обязательна успешная проверка `Format, build, test`;
- перед слиянием ветка должна быть обновлена до актуального `main`, чтобы CI проверял именно тот код, который попадёт в `main`;
- одобрение ревьюера не требуется, так как проект ведёт один разработчик;
- правила распространяются и на администраторов репозитория.

## Деплой

Автоматический деплой контрактов не настроен намеренно. Он потребовал бы хранить приватный ключ в секретах CI, а проект не допускает приватных ключей вне кошелька разработчика. Контракты развёртываются вручную через `forge script`.

## Локальная проверка перед push

Из каталога `contracts/`:

```sh
forge fmt --check
forge build --sizes
forge test
```

# Документация проекта

Эта папка — единая точка входа для владельца, разработчика и нового агента. Документы разделены по назначению, чтобы текущее состояние, устройство системы, причины решений и исторические грабли не смешивались в одном файле.

## Быстрый вход для нового агента

Читайте по порядку:

1. [`project-status.md`](project-status.md) — что уже работает, что проверено и какой следующий этап;
2. [`product-vision.md`](product-vision.md) и [`roadmap.md`](roadmap.md) — что строим и в каком порядке;
3. [`architecture.md`](architecture.md) — текущее устройство контракта и поток средств;
4. [`DECISIONS.md`](DECISIONS.md) — причины решений, которые нельзя восстановить только по коду;
5. [`gotchas.md`](gotchas.md) — ловушки, уже воспроизведённые в этом проекте;
6. документ затрагиваемой подсистемы из таблицы ниже.

## Правила обновления

- Обновляйте документацию в том же PR, который меняет описанное поведение.
- Не копируйте подробный факт в несколько файлов: выберите каноническое место и поставьте ссылки.
- `project-status.md` отражает только настоящее и переписывается при смене этапа.
- В `DECISIONS.md` старое решение сохраняется и помечается заменённым новым.
- В `gotchas.md` попадают только подтверждённые проблемы, а не предположения.
- Публичные адреса, transaction hash и статус верификации записываются в `deployments.md`.
- Временный план после завершения не должен выглядеть как актуальная инструкция. Если его важно сохранить, перенесите его в `docs/archive/` с явной пометкой о завершении.

## Масштабирование документации

Пока документов мало, карту поддерживаем вручную. Когда структура станет достаточно большой, чтобы файлы начали теряться, добавим автоматическую проверку индекса и ссылок. Не создавайте отдельный документ без ссылки из этого индекса или уже индексированного раздела.

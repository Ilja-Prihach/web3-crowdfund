# Текущее состояние проекта

Обновлено: 2 ноября 2026 года. Контрактный этап и Frontend MVP завершены.

## Текущий этап

Контракт V2 с режимами `FixedDeadline` и `OpenEnded` реализован, полностью проверен, влит в `main`, развёрнут и верифицирован в Ethereum Sepolia. Fixed и open-ended сценарии выполнены on-chain через `cast`.

Frontend MVP на Next.js, React и TypeScript завершён десятью PR. PR 1 создал воспроизводимую техническую основу, PR 2 добавил дизайн-систему и application shell, а PR 3 перевёл главную на карточное направление по локальным мокапам: иллюстрированные hero, шаги и режимы, блок доверия со сценой-сейфом, финальный CTA и мобильное меню. PR 4 добавил Web3-основу: wagmi, viem и TanStack Query, сгенерированный ABI, providers с восстановлением сессии из cookie, подключение и смену браузерного кошелька, меню адреса, бейдж сети и переключение на Sepolia. PR 4.1 добавил светлую и тёмную темы с системным начальным значением, сохранением явного выбора и тёмным editorial-направлением «Ночной журнал». PR 5 добавил on-chain-каталог `/campaigns`: чтение `nextCampaignId` и `getCampaigns` без кошелька, карточки со статусом, сроком, прогрессом и обложкой, порядок «сначала новые / старые», пагинацию, локальные фильтры текущей страницы и состояния загрузки, пустого контракта и ошибки RPC. PR 6 добавил страницу кампании `/campaigns/[id]`: проверку ID из адреса, чтение кампании и личного вклада, панель сбора, правила режима, вычисление доступных действий без отправки транзакций и состояния неверного адреса, отсутствующей кампании и ошибки RPC. PR 7 добавил пожертвование: проверку суммы, симуляцию перед подписью, отправку через кошелёк, ожидание блока, перевод ошибок контракта и обновление данных после подтверждения. PR 8 добавил создание кампании `/campaigns/new`: проверку лимитов контракта в байтах UTF-8 до подписи, превью карточки и вызова `createCampaign`, общий жизненный цикл транзакции и переход на новую кампанию по ID из события `CampaignCreated`. PR 9 добавил остальные действия на странице кампании: возврат вклада, отмену, вывод средств и смену срока с переводом ошибок контракта по смыслу конкретного действия. PR 10 провёл приёмку: шапка больше не теряет кнопку кошелька на 960–1279 px, контраст цифр шагов в тёмной теме поднят до 5,28:1, поля ввода уважают reduced motion, а ссылка цепочки навигации получила цель касания 24 px. История этапов — [`archive/frontend-mvp.md`](archive/frontend-mvp.md). Backend остаётся отложенным этапом.

Продуктовая концепция описана в [`product-vision.md`](product-vision.md), порядок этапов — в [`roadmap.md`](roadmap.md).

## Что работает в V2

- создание fixed-кампаний сроком от 1 до 365 дней и open-ended-кампаний без дедлайна;
- изменение дедлайна fixed-кампании creator до первого пожертвования;
- пожертвования в ETH и учёт личных вкладов;
- немедленный успех при достижении цели и запрет последующих пожертвований;
- отмена кампании creator до достижения цели;
- вывод средств сразу после достижения цели;
- возврат вкладов проваленной или отменённой кампании;
- активный возврат из open-ended-кампании до достижения цели;
- вычисляемые статусы кампании;
- ограниченная постраничная загрузка кампаний;
- события для всех финансовых и жизненных переходов кампании;
- deployment через Foundry и чтение состояния через `cast`.

## Проверенное качество

- 77 тестов Foundry проходят локально: unit, fuzz, invariant, transfer-failure и reentrancy-сценарии;
- `forge fmt --check src test script`, `forge lint src/Crowdfunding.sol --deny warnings` и `git diff --check` проходят;
- production-контракт V2 имеет 100% покрытия строк, выражений, веток и функций;
- fixed и open-ended invariant-модели проходят по 128 последовательностей глубиной 100 действий без неожиданных `revert`;
- Slither не нашёл medium/high-проблем; ожидаемые информационные находки по timestamp и low-level `call` проверены вручную;
- gas snapshot обновлён после проверки роста: deployment-тест вырос примерно на 16,9% из-за нового ABI и переходов V2;
- CI проверяет formatting, build, tests, gas snapshot и Slither;
- frontend проходит чистый `npm ci`, ESLint без предупреждений, TypeScript-проверку и production build Next.js;
- application shell проверен в Chromium на 360, 768, 1280 и 1440 px без горизонтального переполнения; подтверждены клавиатурный порядок, видимый skip-link, touch-размеры и `prefers-reduced-motion`;
- карточная главная проверена в Chromium на 360, 390, 768, 1024, 1280 и 1440 px: горизонтального переполнения нет, все внутренние якоря существуют, семь оптимизированных WebP-сцен весят вместе около 103 KB, мобильное меню открывается и закрывается, а desktop и mobile сверены с рендером `home`;
- светлая и тёмная темы проверены в Chromium на 390 и 1440 px: выбор сохраняется после перезагрузки, первый визит следует `prefers-color-scheme`, horizontal overflow отсутствует, переключатель имеет размер 44 px, а его transition отключается при `prefers-reduced-motion`; минимальный измеренный контраст ключевых текстовых пар равен 4,87:1;
- 81 unit-тест frontend (`npm test`) проверяет подсчёт байт UTF-8, правило срока 1–365 дней и проверку черновика кампании по лимитам контракта, разбор суммы ETH из поля ввода, перевод ошибок транзакции на настоящих ошибках viem (revert по ABI с общим словарём и словарём действия, нехватка ETH, отказ), тему, перевод ошибок кошелька, имена кошельков, адрес и аватар, склонение, навигацию выпадающего списка, а также модель кампаний: перевод enum, ответ `getCampaigns`, форматирование ETH, процент, оставшийся срок и дату дедлайна, окна пагинации в обоих направлениях без пересечений и пропусков, разбор ID из адреса и доступные действия для гостя, создателя и участника;
- каталог проверен в Chromium на 390 и 1440 px в светлой и тёмной темах на реальных данных Sepolia: восемь кампаний, существовавших на момент PR 5, совпадают с `cast call getCampaigns`, порядок «сначала новые» начинается с ID 7, horizontal overflow отсутствует; состояние ошибки проверено блокировкой RPC в браузере. Карточка «Отменена» наблюдалась после отмены кампании `8` через интерфейс. Пустой контракт, несколько страниц и карточка «Срок истёк» вживую не наблюдались: таких данных в Sepolia нет, их логика покрыта unit-тестами;
- страница кампании проверена в Chromium на 390 и 1440 px в светлой и тёмной темах для кампаний `0`, `5` и `7`, а также для адресов `/campaigns/abc` и `/campaigns/999`: суммы, режим и даты дедлайна совпадают с `cast call getCampaigns`, horizontal overflow отсутствует. Личный вклад и кнопки создателя с подключённым кошельком проверены в PR 7–9 имитацией кошелька и настоящими транзакциями через Rabby; подпись о фильтрах текущей страницы не наблюдалась, потому что кампаний меньше 21;
- пожертвование проверено в Chromium имитацией EIP-1193-кошелька с адресом deployer, которая пересылает чтения в Sepolia, но не отправляет транзакции: симуляция `donate` проходит по реальному состоянию, кошелёк получает `donate(5)` с `value` ровно `10^15` wei, этапы «подпись», «ожидание сети» и «отказ» отображаются без исключений; все шесть состояний `TransactionStatus` сняты на 390 и 1440 px в обеих темах с временной витрины. первая попытка настоящего вклада через Rabby остановилась на `429` RPC самого кошелька, см. ## Следующий учебный шаг

Frontend MVP завершён, локальный demo-режим (этап 4) отложен, см. [`DECISIONS.md#demo-mode-is-deferred`](DECISIONS.md#demo-mode-is-deferred). Следующий этап — backend и indexer ([`roadmap.md`](roadmap.md#этап-5-backend-и-blockchain-indexer)). Стек выбран: Node.js, TypeScript и Fastify, PostgreSQL с миграциями Drizzle. Модель indexer выбрана: опрос `eth_getLogs` до `finalized` блока, события, проекция и checkpoint в одной транзакции, см. [`DECISIONS.md#indexer-reads-finalized-logs`](DECISIONS.md#indexer-reads-finalized-logs). Публичный RPC frontend не хранит логи с блока deploy, поэтому indexer получает собственный RPC, см. [`gotchas.md#public-rpc-prunes-log-history`](gotchas.md#public-rpc-prunes-log-history). Вход подписью (SIWE), устройство пакета `backend/`, API, обработка обложек и тесты тоже решены, см. указатель [`DECISIONS.md`](DECISIONS.md#указатель). Решений до кода больше не осталось. Создан каркас `backend/`: Fastify с `GET /health`, проверка конфигурации при старте, плавная остановка, единый формат ошибок, ESLint с правилами по типам, 8 тестов и отдельный job CI, см. [`architecture.md#backend`](architecture.md#backend). Подключён PostgreSQL 18.4 из `compose.yaml` через пул `pg` и Drizzle, маршрут `/ready` проверяет базу, тесты и CI работают с настоящей тестовой БД. Следующий шаг — indexer: таблицы событий и checkpoint, первая миграция и чтение логов, в учебном формате с маленькими шагами.

Реальная статистика и блок «Сейчас собирают» на главной пока не сделаны.

## Известные ограничения

- обложку при создании приложить нельзя: контракт не хранит изображений, а хранилище в backend запланировано на этап 5;
- фильтры каталога действуют только на загруженную страницу; сортировка по сумме, поиск и категории ждут indexer;
- в MetaMask со скрытыми тестовыми сетями программное переключение на Sepolia завершалось внутренней ошибкой окна расширения (`Cannot read properties of undefined (reading 'origin')`); причина не подтверждена, обход — включить тестовые сети и выбрать Sepolia вручную, о чём подсказывает полоса неверной сети;
- у backend есть каркас и подключение к PostgreSQL; таблицы, indexer и API каталога ещё не созданы;
- `npm audit` находит в dev-зависимостях две moderate-находки, не затрагивающие production: minimatch (GHSA-g3hv-75wg-m249) внутри `typescript-eslint` во frontend и backend и esbuild 0.18 (GHSA-67mh-4wv8-2f99) внутри `drizzle-kit`; шаблоны minimatch берутся только из нашего конфига ESLint, а dev-сервер esbuild не запускается. `npm audit --omit=dev` чистый в обоих приложениях; install-скрипты esbuild в backend запрещены через `allowScripts`;
- контракт развёрнут только в тестовой сети, Mainnet deployment не планируется на текущем этапе;
- исходники подтверждены Sourcify, но отдельно через Etherscan API не верифицировались;
- актуальная Sepolia оценивает deployment gas значительно выше локальной Cancun-симуляции; перед любым следующим deployment требуется новый RPC estimate, см. [`gotchas.md`](gotchas.md#sepolia-deployment-gas-differs-from-local-simulation).

# Тесты смарт-контрактов

Тесты написаны на Foundry и разделены по назначению:

- `Crowdfunding.t.sol` проверяет создание кампаний, пожертвования, вывод средств, возвраты и защиту от повторного входа;
- `CrowdfundingTransferFailures.t.sol` проверяет несуществующие кампании и откат состояния при неудачной отправке ETH;
- `CrowdfundingWithdrawReentrancy.t.sol` проверяет защиту вывода средств от повторного входа вредоносного creator-контракта;
- `CampaignFundingModes.t.sol` проверяет создание open-ended-кампаний, ограничения длительности, ранний успех и активный возврат;
- `CampaignDeadlineUpdate.t.sol` проверяет права и ограничения изменения дедлайна до первого пожертвования;
- `CampaignCancellation.t.sol` проверяет права доступа, переход в статус отмены, запрет пожертвований и вывода, а также возвраты донатерам;
- `CampaignStatus.t.sol` проверяет вычисляемые статусы кампаний;
- `CampaignPagination.t.sol` проверяет постраничное чтение, вычисляемые статусы, сокращённую последнюю страницу, пустой результат и ограничения размера страницы;
- `CrowdfundingFuzz.t.sol` проверяет финансовые свойства на автоматически сгенерированных входных данных;
- `invariant/CrowdfundingInvariant.t.sol` моделирует fixed-кампанию, отмену и возвраты;
- `invariant/OpenEndedCrowdfundingInvariant.t.sol` моделирует активные возвраты, достижение цели и вывод open-ended-кампании;
- `invariant/` содержит handlers с независимым ghost-учётом для обеих моделей;
- `helpers/` содержит вспомогательные контракты для моделирования атак и других специальных сценариев.

## Unit-тесты

Unit-тесты используют заранее выбранные значения и проверяют конкретные успешные и ошибочные сценарии.

## Fuzz-тесты

Fuzz-тесты принимают аргументы, для которых Foundry автоматически генерирует множество значений. Числовые входы ограничиваются через `bound`, когда тесту нужна определённая допустимая область.

Каждый fuzz-тест выполняется 256 раз. Текущие свойства проверяют:

- точный учёт любого положительного пожертвования;
- накопление нескольких пожертвований одного адреса;
- возврат точной суммы после провала кампании;
- согласованность `totalRaised`, баланса и вкладов после активного возврата из `OpenEnded`.

## Invariant-тесты

Invariant-тесты генерируют случайные последовательности действий и проверяют свойства, которые должны оставаться истинными после любого допустимого порядка вызовов.

`CampaignHandler` моделирует трёх донатеров и создателя кампании. Foundry случайно вызывает действия `donate`, `cancel` и `refund`. Handler ограничивает суммы через `bound`, выполняет вызовы от нужных адресов и превращает недопустимые для текущего состояния действия в no-op через защитные условия.

Ghost-переменные независимо учитывают общую сумму пожертвований, возвраты, текущие вклады донатеров и состояние отмены. Они обновляются только после успешного вызова production-контракта.

Fixed invariant-модель использует цель, недостижимую в заданном диапазоне действий. Это позволяет исследовать donation, cancellation и refund без перехода в успешное состояние.

Open-ended invariant-модель генерирует donation, активные refund и withdraw. Её достижимая цель позволяет исследовать переходы `Active → Successful → Withdrawn` и порядок donation/refund до успеха.

Текущие инварианты проверяют, что:

- `totalRaised` равен общей сумме пожертвований за вычетом возвратов;
- баланс контракта равен `totalRaised`;
- вклад каждого донатера совпадает с ghost-учётом;
- сумма текущих вкладов равна `totalRaised`;
- состояние `cancelled` совпадает с fixed ghost-моделью;
- после open-ended-вывода баланс контракта равен нулю, а до вывода — `totalRaised`;
- open-ended-статус согласован с текущей суммой и фактом вывода.

Для каждой модели Foundry выполняет 128 последовательностей глубиной до 100 действий. Любой неожиданный `revert` handler считается ошибкой.

## Gas snapshot

Gas snapshot хранит базовые показатели расхода gas для стабильных unit-тестов. Fuzz- и invariant-тесты исключены, потому что их показатели могут меняться из-за сгенерированных входных данных.

Создать или обновить snapshot:

```bash
forge snapshot --no-match-contract "Fuzz|Invariant"
```

Сравнить текущие показатели с сохранёнными:

```bash
forge snapshot \
  --no-match-contract "Fuzz|Invariant" \
  --diff
```

Проверить полное совпадение:

```bash
forge snapshot \
  --no-match-contract "Fuzz|Invariant" \
  --check
```

Изменение gas не всегда является ошибкой. Перед обновлением snapshot нужно понять причину разницы и убедиться, что она ожидаема.

## Запуск

Все тесты:

```bash
forge test
```

Только fuzz-тесты с подробной статистикой:

```bash
forge test --match-contract CrowdfundingFuzzTest -vv
```

Все invariant-тесты с подробной статистикой:

```bash
forge test --match-path "test/invariant/*.t.sol" -vv
```
